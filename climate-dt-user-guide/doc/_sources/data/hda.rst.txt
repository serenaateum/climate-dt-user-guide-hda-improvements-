Harmonised Data Access (HDA)
=============================

The Harmonised Data Access (HDA) service provides access to the DestinE
Data Portfolio, including Climate DT outputs, through a STAC-compliant
API.

STAC (SpatioTemporal Asset Catalog) is a widely adopted standard for the
description, discovery, and access of geospatial data. By exposing
Climate DT datasets through STAC, HDA enables users to discover and
access Climate DT simulations using a common interoperability framework
that is already supported by numerous geospatial tools, libraries, and
platforms.

This approach facilitates the integration of Climate DT simulations with
other Earth observation, climate, environmental, and geospatial datasets,
allowing users to build workflows that span multiple data sources while
relying on a standard metadata model and access interface.

In STAC, a collection is a dataset, or a group of closely related datasets, described through a common set of metadata. In the context of Climate DT, HDA collections correspond to the available simulation datasets and provide the metadata needed to discover, filter, and retrieve the associated Climate DT data.

More detailed information on the HDA service is available in the
Destination Earth Data Lake documentation:
https://destine-data-lake-docs.data.destination-earth.eu/en/latest/dedl-discovery-and-data-access/Harmonized-Data-Access/Harmonized-Data-Access.html


Prerequisites and access methods
---------------------------------

.. admonition:: Prerequisite

   A DestinE Platform account with upgraded access is required. `Apply for upgraded
   access here <https://platform.destine.eu/access-policy-upgrade/>`_.

There are several ways to access and use the HDA API:

- **On your local machine**
  - Python 3.9 or later, together with one or more python libraries such as `Requests`, `PySTAC`, or `EODAG`; or
  - curl for command-line access.

- **Through Insula Code or the DestinE Data Lake STACK**
  - Browser-based Jupyter environments provided by the DestinE Platform and the DestinE Data Lake, with the required software already available.


Authentication
--------------

A DestinE Platform authentication token is required to use HDA. The recommended way is to use the [destinelab](https://pypi.org/project/destinelab/) library:



::

import destinelab as deauth
import requests
import json

auth = deauth.AuthHandler(DESP_USERNAME, DESP_PASSWORD)
access_token = auth.get_token()

auth_headers = {"Authorization": f"Bearer {access_token}"}

HDA_STAC_ENDPOINT="https://hda.data.destination-earth.eu/stac/v2"
COLLECTION_ID="EO.ECMWF.DAT.D1.DT_CLIMATE.G2.PROJECTIONS_SSP3-7.0_IFS-FESOM.R1"

hdaFilters={
    "ecmwf:resolution": {
        "eq": "standard"
    },
    "ecmwf:levtype": {
        "eq": "sfc"
    },
    "ecmwf:param": {
        "eq": [
            "228004"
        ]
    },
    "ecmwf:stream": {
        "eq": "clmn"
    },
    "ecmwf:year": {
        "eq": [
            "2030"
        ]
    },
    "ecmwf:month": {
        "eq": [
            "9"
        ]
    },
    "ecmwf:levelist": {
        "eq": [
            "2"
        ]
    }
}

search_body = {
     "collections": [COLLECTION_ID],
     "query":  hdaFilters
}  

response = requests.post(HDA_STAC_ENDPOINT+"/search", headers=auth_headers, json=search_body)

Climate DT Collections in HDA
-----------------------------

Climate DT simulations are exposed through the Harmonised Data Access (HDA)
service as individual STAC collections.

Each collection represents a specific Climate DT simulation and follows a
structured naming convention encoding the main simulation attributes. For
example the following collection identifier:

::

   EO.ECMWF.DAT.D1.DT_CLIMATE.G2.PROJECTIONS_SSP3-7.0_IFS-FESOM.R1

follows the naming convention below:

* ``D1`` identifies the DestinE Climate DT data class;
* ``G2`` identifies the simulation generation (Generation 2);
* ``PROJECTIONS`` identifies the simulation activity;
* ``SSP3-7.0`` identifies the climate scenario;
* ``IFS-FESOM`` identifies the model;
* ``R1`` identifies the first realization.

This naming convention enables users to quickly identify the simulation
characteristics directly from the collection identifier.


STAC Metadata for HDA Climate DT Collections
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The Harmonised Data Access service exposes Climate DT simulations through
a [STAC-compliant API](https://docs.ogc.org/cs/25-005/25-005.html).

Each collection contains extensive metadata describing the corresponding
Climate DT simulation, including:

* collection description;
* temporal coverage;
* available parameters along with their information (cube:variables);
* the associated data bridge - LUMI, MARENOSTRUM or LEONARDO - (federation:backends);

Users can inspect the complete metadata associated with a collection by
opening the collection endpoint directly. For example:

`Climate Change Adaptation Digital Twin (Climate Adaptation DT) - Future Projection - IFS-FESOM - Generation-2 - Realization-1 <https://hda.data.destination-earth.eu/stac/v2/collections/EO.ECMWF.DAT.D1.DT_CLIMATE.G2.PROJECTIONS_SSP3-7.0_IFS-FESOM.R1>`_   

and look at the metadata of one of the available parameter:

Discovering Climate DT Variables and Query Parameters
-----------------------------------------------------

The STAC Queryables endpoint provides a machine-readable description of the
dimensions and request parameters available within a Climate DT collection.
It can be used to discover which filters are supported and to construct
valid HDA search and retrieval requests programmatically.

For example, the queryables endpoint for the high-resolution version of the
IFS-FESOM SSP3-7.0 projection simulation can be inspected at: https://hda.data.destination-earth.eu/stac/v2/collections/EO.ECMWF.DAT.D1.DT_CLIMATE.G2.PROJECTIONS_SSP3-7.0_IFS-FESOM.R1/queryables?ecmwf:resolution=high

The response describes the available dimensions, their valid values, and
their corresponding metadata. Typical examples include variables, level type, temporal frequency,
resolution, and other collection-variable-specific fields.

The Queryables endpoint is also the recommended mechanism for discovering
which Climate DT variables are available within a given simulation. This
allows users to dynamically inspect the content of a collection without
having to rely on static variable lists.

A practical example showing how to inspect and use the Queryables endpoint
is available in the DestinE DataLake Lab notebook: https://github.com/destination-earth/DestinE-DataLake-Lab/blob/main/HDA/REST/HDA-REST-Queryables.ipynb


Polytope Feature Parameter
~~~~~~~~~~~~~~~~~~~~~~~~~~

In addition to the parameters described by the Queryables endpoint,
Climate DT collections support the Polytope ``feature`` parameter for
variable selection.

The ``feature`` parameter is not described in the Queryables
response, but it can be used in HDA requests following the same syntax and
semantics used by the Polytope service. This allows users already familiar
with Polytope workflows to seamlessly transfer existing requests and
variable-selection patterns to HDA-based workflows.

Additional information about the ``feature`` parameter is available in the
Polytope documentation: https://polytope.readthedocs.io/en/latest/Service/Features/feature/

.. hint::

   A recommended workflow is to first inspect the collection metadata,
   then explore the Queryables endpoint to discover available dimensions
   and variables, and finally construct the HDA request using the desired
   filters and Polytope-compatible parameters where applicable.


Climate DT Discovery and Access Workflow - Interactive Exploration
-----------------------------

The typical workflow consists of:

#. Discover the available Climate DT collections.
#. Identify the simulation of interest.
#. Explore collection metadata.
#. Select variables and temporal range.
#. Submit an HDA request.
#. Download or analyse the returned assets.
